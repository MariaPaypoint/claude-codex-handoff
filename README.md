# Claude–Codex Handoff

Скилл для **Claude Code**, который помогает поручать задачи **Codex CLI**:
Claude ставит задачу и проверяет результат, Codex работает с кодом в отдельной
сессии и возвращает краткий отчёт.

Чтение файлов, промежуточные правки и длинные логи остаются в сессии исполнителя.
Это помогает сохранять контекст Claude компактным при многошаговой работе.

## Установка

Нужны установленные и авторизованные [Claude Code](https://code.claude.com/docs/en/overview)
и [Codex CLI](https://developers.openai.com/codex/cli/), а также Git.
Команда `codex` должна быть доступна из терминала, который использует Claude.

```bash
git clone https://github.com/MariaPaypoint/claude-codex-handoff.git \
  "$HOME/.claude/skills/claude-codex-handoff"
```

Открой новую сессию Claude Code в своём проекте. Скилл можно вызвать явно:

```text
/claude-codex-handoff Поручи Codex добавить обработку пустого результата
в модуле поиска и релевантный тест. Проверь изменения перед завершением.
```

Или попросить обычным текстом:

```text
Используй claude-codex-handoff. Передай Codex рефакторинг этого модуля,
а сам проверь результат. Публичный API должен остаться прежним.
```

Для обновления:

```bash
git -C "$HOME/.claude/skills/claude-codex-handoff" pull --ff-only
```

Скилл устанавливается в Claude Code: он содержит инструкции для оркестратора.
Codex получает конкретное задание через CLI. Отдельно устанавливать этот скилл
в Codex не требуется. Подключения и авторизация двух инструментов независимы.

## Что внутри

- [SKILL.md](SKILL.md) — выбор задач, запуск `codex exec`, продолжение по ID,
  права, параллельная работа, независимое ревью и приёмка.
- [`scripts/codex-ctx.sh`](scripts/codex-ctx.sh) — текущий размер контекста
  сессии Codex и доля окна.
- [Шаблон задания](references/prompt-template.md) — контекст, границы,
  критерии проверки и формат handoff.

Установка добавляет текстовые инструкции. Она не меняет глобальные настройки,
не подключает сервисы и не запускает Codex автоматически.

## Как работает передача

1. Claude проверяет состояние проекта и пишет ограниченное задание в файл.
2. Запускает Codex в нужном репозитории с явно выбранными правами.
3. Codex вносит изменения, проверяет их и сохраняет итоговый handoff.
4. Claude сверяет отчёт с diff и подтверждает критерии приёмки.
5. Доработки идут в ту же сессию по точному ID; независимое ревью — в новую.

Для работы с визуальными критериями нужен доступный браузер у проверяющего
агента. Скилл не добавляет браузер или MCP-инструменты. Если основная работа —
ручная визуальная проверка небольшой правки, делегирование может не окупиться.

Модель, провайдер и лимиты задаются вашими настройками Claude Code и Codex.
Скилл не фиксирует модель и не обещает конкретной экономии токенов или денег.

## Совместимость

Примеры рассчитаны на Bash/Zsh в macOS/Linux. В Windows используйте WSL или
адаптируйте команды к своей оболочке. У Codex должен быть доступ к целевому
репозиторию и необходимым инструментам проекта.

На 16 сентября 2026 года флаги примеров сверены с `codex-cli 0.154.0`
через `codex exec --help` и `codex exec resume --help`, а поведение stdin,
handoff, сессий и прав — с официальной документацией:

- [Non-interactive mode](https://developers.openai.com/codex/noninteractive/)
- [Agent approvals & security](https://developers.openai.com/codex/agent-approvals-security/)
- [Claude Code skills](https://code.claude.com/docs/en/skills)

Это проверка интерфейса команд и документации, а не гарантия работы всех
комбинаций ОС, провайдеров и подключений. Перед первым запуском проверьте
`codex --version` и авторизацию в своём окружении.
